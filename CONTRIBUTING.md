# Contribuir a xTender

Gracias por ayudar a construir herramientas abiertas para la contratación pública. Puedes aportar código, documentación, traducciones, accesibilidad, casos de uso y pruebas con datos sintéticos.

## Antes de empezar

Consulta el [README](README.md), el [roadmap](ROADMAP.md) y las issues abiertas. Para un cambio amplio, abre primero una propuesta con el problema, el recorrido de usuario y los criterios de aceptación. Las correcciones pequeñas pueden llegar directamente como pull request.

## Flujo de trabajo

1. Haz un fork y crea una rama descriptiva.
2. Sigue la guía de instalación del repositorio y usa configuración local propia.
3. Implementa un cambio acotado. Mantén las decisiones humanas, el aislamiento por entidad y la trazabilidad existentes.
4. Ejecuta las comprobaciones documentadas y añade una prueba si cambia un comportamiento que lo necesita.
5. Abre una PR explicando problema, solución, validación y limitaciones.

Usa ejemplos inventados. No adjuntes expedientes reales, pliegos, anexos, ofertas, datos personales, credenciales, volcados ni sus extracciones Markdown/JSON. Los fallos de seguridad se comunican por el canal de [SECURITY.md](SECURITY.md).

## Revisión y licencia

Las contribuciones se revisan antes de incorporarse. Al enviarlas confirmas que puedes compartirlas bajo Apache 2.0; conserva los avisos de terceros que correspondan. El archivo `private: true` de npm evita publicaciones accidentales del paquete y no cambia la licencia del código.

Participar implica respetar el [código de conducta](CODE_OF_CONDUCT.md).

La contribución no transfiere tu titularidad al proyecto. La distribución mantiene las condiciones de Apache 2.0 y de los [componentes de terceros](THIRD_PARTY_NOTICES.md).
